# Threat model and TCB — S1

## What is being protected
The link *statement ⇄ proved proposition ⇄ semantics*: that a Signed Statement asserting
`NotDemonstrated(reason=underdetermined)` for instance bytes `B` under profile digest `P` and verifier manifest `V`
is backed by a Lean kernel proof of exactly `P10.Bound B digest(B)` under the semantics whose digest is bound in `V`.

## Trusted computing base (explicit)
| Component | Why trusted | Mitigation / evidence |
|---|---|---|
| Lean 4.33.0 kernel + `lean` binary + `libleanshared.so` | kernel checks proofs | exact binary and shared-lib SHA-256 in the manifest; pinned package digest in `install_toolchain.sh` |
| `P10/Bytes.lean` (`bytes%`, `filebytes%`, `hex%` elaborators) | meta code (not kernel-checked) turns text/files/hex into `List Nat` literals | the kernel sees the fully expanded literal; `N5–N9` must-fail tests; the checker-owned statement is regenerated by the verifier from the statement's stated digest |
| `P10/Sha256.lean` | hashing inside the kernel; **not proved correct** | FIPS 180-4 vectors checked by the kernel; differential test vs `hashlib` on 17 lengths incl. padding boundaries; zero axioms |
| `scripts/p10tool.py` | SHA-256 of profile/source files, JCS of the statement, COSE verification (pycose), orchestration, checker-owned Lean file generation | hashed in the manifest (`verifier_scripts_digest`); mutation suite exercises it; TEST-key-only acceptance |
| `scripts/lint_lean.py`, `run_tests.py`, `verify.sh` | gate logic | hashed in the manifest |
| Python libs (`pycose`, `cbor2`, `cryptography`) | COSE decoding/signature | versions pinned in `requirements.lock` (`verify.sh` checks pycose/cbor2) |
| The profile text | normative | byte-identical snapshot; digest checked in three places (script constant, Lean `specTok`, statement) |

Not in the TCB: the Python decoder mirror (differential-tested against the Lean decoder, never authoritative); any runtime.

## Adversaries considered and outcome (see `scripts/mutation_suite.py`)
| Attack | Result |
|---|---|
| Mutate profile bytes / semantics / decoder / claim / evidence / w0 / w1 / manifest / toolchain / lakefile | REJECT |
| Attacker regenerates manifest **and** statement and re-signs (test key is public) | REJECT by manifest pin; without the pin, REJECT by Lean when semantics/instance change |
| Stale statement with a new profile | REJECT (profile digest chain) |
| Certificate proves a weaker/different proposition, or another vector's proposition | REJECT (type mismatch against the checker-owned statement) |
| `sorry` / `native_decide` / added `axiom` certificate | REJECT (axiom output must be exactly "does not depend on any axioms") |
| Runtime emits `NotDemonstrated` with no/invalid certificate | REJECT — runtime has **no epistemic authority** |
| Runtime with different internal semantics attaches the old certificate | REJECT (semantics digest) |
| Different `lean` executable with the same `--version` string | REJECT (executable digest) |

**Documented residual:** a *self-consistent alternative tree* (all sources, manifest, statement regenerated) is
accepted as a *different verifier* unless its manifest digest is pinned (`INFO-benign-regen-unpinned` case). This is why
the profile commits `verifier_manifest_digest` in `InstanceCommitment`; S1 emulates the commitment with
`profile/VERIFIER_MANIFEST_PIN.txt` and `--manifest-digest`. Anchoring that pin externally (e.g. registering it) is S3.

## Out of scope (NOT DEMONSTRATED)
Model adequacy of any profile; truthfulness of evidence; runtime decision-time use (Wadkins DET-2 style);
completeness/omission (profile §§2.4–2.6); log integrity and SCITT; collision resistance of SHA-256 and Ed25519
unforgeability (assumed); side channels; a malicious `lake`/OS.

## Elaboration-time execution
Building or verifying runs Lean elaboration of the committed sources, including `P10/Bytes.lean` meta code. Do not
run the verifier on unreviewed source trees expecting isolation; use a disposable environment.
